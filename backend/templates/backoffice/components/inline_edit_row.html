{# ABOUTME: One value of a details list edited in place: the value with a pencil, or a field with a tick and an X ABOUTME: Rendered with its page, and on its own by the route it posts to, whose answer htmx swaps in for the row #} {% from "backoffice/components/button.html" import button %} {% from "backoffice/components/icons.html" import icon_check, icon_close, icon_pencil %} {% from "backoffice/components/info_icon.html" import info_icon %} {% from "backoffice/components/input.html" import input, textarea %} {# A row of a details list whose value is edited where it is shown, as on the project details design: the pencil at the end of the row turns the value into a field and itself into a tick, with a red X beside it. The tick, Enter or leaving the row saves; the X or Escape puts the stored value back. The behaviour is the inlineEdit component (src/js/components/inline-edit.js). Neither the tick nor the X takes focus from the field when pressed (@mousedown.prevent). Safari does not focus a pressed button at all, so otherwise the field would blur to the page, which counts as leaving the row - and leaving the row saves, even on the way to the X. The row is a form posting to `action`. htmx sends it on the component's "inline-edit-save" event rather than on submit, so an unchanged value is never sent, and swaps the server's answer in for the whole row: the row at rest after a save, still open with the reason under the field after a refusal. Without htmx the form posts like any other. In a textarea Enter adds a line, so Ctrl+Enter (Cmd+Enter) saves instead; the tick and leaving the row save as they do everywhere. Used by My account (profile/_name_row.html) and the project details page (project_details/_rows.html). Args: row_id: The id of the row, which htmx swaps the answer in for field: The form field's name, posted as `field` and as the value's name label: The row's term, and the field's label value: The stored value, as the field holds it action: Where the form posts edit_label, save_label, cancel_label: The names of the pencil, the tick and the X - "Edit first name", "Save first name", "Cancel editing first name" kind: "text", "textarea", "number" or "date" - which control edits it display: The value as text at rest, when that differs from `value` (a formatted date). An empty value reads "Not set". submitted: What was typed, when it was refused; defaults to the value error: Why it was refused. A row with an error opens still editing, the field focused. return_focus: The save came from inside the row (the tick or Enter): focus the pencil once htmx has swapped the row in field_attrs: Extra attributes for the control input_id: The control's id; defaults to the field name editable: False for someone who may read the value but not change it: the row has no pencil and no form label_info: A sentence about the value, behind an info icon beside the label #} {% macro inline_edit_row(row_id, field, label, value, action, edit_label="", save_label="", cancel_label="", kind="text", display=none, submitted=none, error="", return_focus=false, field_attrs="", input_id="", editable=true, label_info="") %} {% set value = value if value is not none else "" %} {% set shown = display if display is not none else value %} {% set editing = error | length > 0 %} {% set input_id = input_id or field %} {% set control_attrs = 'x-ref="field" ' ~ field_attrs ~ (' autofocus' if editing else '') %} {# Padded so the row is as tall as its neighbours with the text on the same line, the field taking the room the text at rest leaves around it. #}

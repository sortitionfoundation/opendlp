# 919 — Signup survey backend plan

Issue #919 lets people create an account without an invite code (behind the
`FF_OPEN_SIGNUP` feature flag) and asks them optional qualification questions
at registration. The frontend — question spec, registration form, admin
display, CSV export UI — is done and merged behind the flag. What it calls is
currently a **mock service module**; this document specifies the real backend
that replaces it.

**Reference implementation:** the branch `919-reference-implementation`
(commit `aa79f38e`) contains a complete, tested end-to-end implementation of
everything below, written before the work was split along team lines. Treat it
as a worked example to crib from freely — but re-review it as your own, and
note it predates the mock-module seam, so its service functions live in
`user_service.py` and its blueprints/tests import from there.

## The seam

`src/opendlp/service_layer/signup_survey_service.py` is the contract. The
blueprints (`auth.py`, `admin.py`) and the tests import three functions from
it:

- `save_signup_survey(uow, user_id, answers: dict[str, str]) -> None`
- `get_signup_survey(uow, user_id, admin_user_id) -> UserSignupSurvey | None`
- `export_users(uow, admin_user_id, *, target: AbstractTabularExportTarget) -> None`

The mock already implements the real permission checks (admin-only for get and
export, via `has_global_admin`), the real empty-answer handling, and the real
CSV table building. Only the storage is fake: a module-level dict. **Keep the
module path and signatures; replace the dict with a repository.** Nothing in
entrypoints or the tests should need to change. Delete
`reset_mock_survey_store()` when the dict goes.

## Storage

New table `user_signup_surveys`, one optional row per user:

| column     | type                          | notes                                   |
|------------|-------------------------------|-----------------------------------------|
| id         | UUID PK                       | default uuid4                           |
| user_id    | UUID FK -> users.id           | `ondelete="CASCADE"`, unique, indexed — GDPR erasure rides the cascade |
| answers    | JSON, not null                | dict of question key -> answer string   |
| created_at | TZAwareDatetime, not null     | default `aware_utcnow`                  |

- Domain model `UserSignupSurvey` already exists in
  `domain/user_signup_surveys.py` (plain Python: drops empty answers in
  `__init__`, `has_any_answers()`, `create_detached_copy()`, equality by id).
  The same module holds `SIGNUP_SURVEY_QUESTIONS` (the question spec that
  drives form/admin/export) and `leftover_answer_keys()`.
- Define the table in `adapters/orm.py` next to `user_invites`; map it
  imperatively in `adapters/database.py` (no relationship needed).
- Migration: `uv run alembic revision --autogenerate -m "add user_signup_surveys table"`.
  The reference migration is `ef642787cb4a` — note it imports
  `orm.TZAwareDatetime` and plain `JSON` rather than the autogenerated
  `opendlp.adapters.orm.…` references.
- House rule: add `orm.user_signup_surveys.delete()` to
  `_delete_all_test_data()` in `tests/conftest.py` and to
  `delete_all_except_standard_users()` in `tests/bdd/conftest.py`
  (before the `users` delete).

## Service functions (real versions)

- `save_signup_survey`: build `UserSignupSurvey(user_id=…, answers=…)`; if
  `not survey.has_any_answers()`, store nothing (a row must always mean the
  user said something); else `uow.user_signup_surveys.add(survey)` and log
  the answered keys only — answers are personal data, never log values.
- `get_signup_survey`: admin check (same pattern as `get_user_by_id`), then
  `get_by_user_id`, returning a detached copy or None.
- `export_users`: admin check; load all surveys into a `user_id -> survey`
  dict; columns = fixed user columns (`email, first_name, last_name,
  global_role, active, created_at, email_confirmed_at`), then one column per
  spec question **keyed by question key** (stable across UI languages), then
  sorted leftover keys from `leftover_answer_keys()` so answers to removed
  questions are never silently dropped; rows ordered by `created_at`; write
  one sheet named `"users"` via `target.write_sheet`.

## OAuth registration (not yet wired — frontend deliberately skipped it)

Google/Microsoft registration is still invite-only even with the flag on.
To extend open signup to OAuth (reference branch has all of this working):

1. `find_or_create_oauth_user` gains `open_signup_role: GlobalRole | None = None`;
   when creating a new user with no invite code: raise `InvalidInvite` if it
   is None, else `create_user(..., global_role=open_signup_role)`. An invite
   code, when given, still wins.
2. Callbacks (`google_callback`, `microsoft_callback`) pass
   `open_signup_role=GlobalRole.ORGANISER if has_feature("open_signup") else None`,
   and when `created` is true call `save_signup_survey(uow, user.id,
   session.get("oauth_survey_answers") or {})` inside the same `with uow:`;
   pop `oauth_survey_answers` with the other oauth session keys.
3. `register_google` / `register_microsoft` routes: drop the
   `assert form.invite_code.data is not None`, stash
   `session["oauth_survey_answers"] = form.survey_answers() if show_questions else {}`
   where `show_questions = has_feature("open_signup") and request.args.get("skipq") != "1"`,
   and pass `show_questions` to the template.
4. `OAuthRegistrationForm`: add `SignupSurveyFormMixin`, switch `invite_code`
   validators to `[InviteCodeRequiredUnlessOpenSignup(), Length(min=5, max=50)]`
   (both already exist in `forms.py`, used by `RegistrationForm`).
5. Templates `register_google.html` / `register_microsoft.html`: same
   conditional inset-text / invite-hint / `signup_survey_fields(form)` blocks
   as `register.html`; also make `register.html`'s OAuth section heading
   conditional on the flag again ("with an external account" vs "… and an
   invite code").

**WTForms trap, learned the hard way:** do not put `Optional()` on the invite
field. It stops the whole chain on an empty field *including inline
validators*, and it **clears `field.errors`** before stopping — wiping the
required-error a preceding validator just raised. That is why
`InviteCodeRequiredUnlessOpenSignup` raises `StopValidation` itself (with a
message when the code is required, silently when an empty code is allowed).

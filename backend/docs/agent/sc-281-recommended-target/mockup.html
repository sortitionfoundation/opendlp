sc-281 Stratified selection improvements · Epic 426

Implement recommended target changes from a failed selection

When you run the initial selection at the end of recruitment, the algorithm may tell you the targets can't be met — but that a few adjustments would fix it. The failure view tells you what to change; it gives you no way to do it. You open the Targets tab and apply the numbers by hand, juggling two tabs: one with the suggestions, one with the editor.

sc-281 wires the fix into the place the problem appears: an Adjust targets link on the failed run takes you straight to the targets check with the suggestions showing, where one-click Accept buttons apply them — and, since you came from a run, offer to re-run the selection.

type Feature priority High pattern from sc-447 replacements entry Selection failure view
01

Where it breaks today

The trigger. Running the initial selection fails on infeasible quotas. The run's failure view already lists the adjustments the solver suggests — as read-only prose. There's no action there, so it's a dead end.

The workaround. Open the Targets tab in another window, run the check, and retype each suggested minimum/maximum by hand — keeping both tabs open to copy between them.

The fix. A link from the failure view to targets/check?from=selection (check already run), where each suggestion carries an Accept button, plus Accept all and — because you arrived from a run — Accept all & re-run selection. Accepting also records an audit comment on the value.

03

User flow

From running the selection to a feasible — or freshly running — selection, without leaving for a second tab.

STEP 1

Run initial selection → fails

Quotas are infeasible; the failure view lists the adjustments.

STEP 2 · new

Adjust targets

One link to targets/check?from=selection — the check is already run, suggestions showing.

STEP 3

Accept

Per suggestion or Accept all. Server applies the value and records an audit comment.

STEP 4a

Re-check

Fresh feasibility — the accepted suggestion is gone.

STEP 4b · from run

…& re-run

Because you came from a run, go straight to a live selection in the same click.

NOTE

Direct visit

Reaching targets by editing + saving (no run) shows Accept, but no re-run button.

04

Data flow

The new route re-derives the suggestions itself (never trusting posted numbers), applies each through the existing target-value service — writing the audit comment — then branches to a re-check or, only when you came from a run, a fresh selection.

request / apply re-check branch re-run branch (from run only) reused, unchanged
05

Scope & decisions

Entry point

Failed selection view. An Adjust targets link bridges to the targets check — the fix starts where the problem shows.

Action

Per-suggestion Accept + Accept all on the targets check, mirroring sc-447.

Re-run

Gated on provenance. “Accept all & re-run” only when you came from a run (from=selection).

Comment — open

Auto-written or review-before-save. Demonstrated both in the prototype; pick one.

In scope

  • Link from the failed initial-selection view to the targets check.
  • One-click accept of a recommended min/max, server-side, with an audit comment.
  • Accept-all, and accept-all-and-re-run when arriving from a run.

Out of scope

  • Side-by-side “review in context” original-vs-new edit page.
  • Anything replacement-specific (original targets, saved-number handling).
  • Changing how suggestions are computed — reused as-is.
06
